## 第一章：数据源通道分级与分工协同原则

1. **第一顺位（首选专线通道与市场严格分工）**：
   - 对于所有**结构化、高频、定量的核心金融数据**，**必须首先调用 MCPHub 证券专属工具**。
   - **底层通道严格市场分工**：
     - **国内市场专属通道（通达信官方专线 TDX）**：全面负责国内市场（A 股沪深北主板、创业板、科创板、内地基金、大盘指数）。提供 Level-1 基础五档买卖盘口、复权 K 线、纯 Python 原生技术指标计算、权威财务三张表、主力资金博弈与 F10 深度题材。
     - **港股市场专属通道（腾讯免费数据接口）**：专门负责港股市场（5 位数字代码标的，如腾讯 `"00700"`、美团 `"03690"`）。突破通达信免费账号无港股权限的技术限制，提供港股实时价格、买卖一档盘口及多周期 K 线走势。
   - 专线调用由 MCPHub 网关底层根据股票代码位数（6位 vs 5位）自动智能分流路由，调用端无需手动切换服务端点。

2. **第二顺位（搜索备份与兜底降级通道）**：
   - 当遇到以下场景时，主动启用通用搜索工具（`fallback_web_search` 或 `multi_web_search`）作为后备兜底：
     - **专线偶发超时或数据缺失**：如冷门未上市标的、特殊跨境衍生品、部分海外个股等专线未收录资产；
     - **专线服务熔断告警**：在极端网络故障或专线报异常时，平滑降级至网页搜索，保证服务不中断。

3. **第三协同（全网多源交叉印证通道）**：
   - 金融市场受信息不对称和突发消息影响显著。当面临以下定性任务时，应与专线数据**联合协同、互相印证**：
     - **重大突发传闻核实**：如盘中传出重组、立案调查、借壳或重大政策变化，先用 `stock_news` 查看官方公告，再通过 `multi_web_search` 交叉比对主流财经媒体与行业报道；
     - **宏观与行业背景穿透**：结合 `fallback_web_extract` 精读权威财经研报正文，与专线计算的技术面形成“宏观背景+微观盘口”的立体研判。

4. **工具命名绝对一致律（核心红线）**：
   - MCP 协议要求工具标识符严格匹配。所有接口**绝不能带有 `tdx_`、`hub_` 等任何自定义前缀**。
   - 必须严格使用下文登记的 8 大标准原始名称（如 `stock_quotes`、`stock_kline`），任何前缀拼接均会导致底层抛出 `Tool not found` 致命异常。

5. **代码先行与实体预解析律**：
   - 在未获取确切的标准数字证券代码前，**必须先执行 `stock_lookup` 获取精确代码**，严禁凭大模型自身记忆猜测 6 位 A 股代码或 5 位港股代码。

6. **防计算幻觉律（技术指标零心算）**：
   - 大模型严禁自主心算 MACD 金叉/死叉、MA 均线点位或布林带上中下轨数值。
   - 调用 `stock_kline` 时默认开启 `with_indicators=true`，直接读取网关纯 Python 算法毫秒级计算出的精确技术指标序列，模型只负责逻辑研判。

7. **PE 双轨防误导与指明律（严禁混称市盈率）**：
   - 接口同时提供两种不同口径的市盈率，大模型在研报、分析与回答中**必须明确标注具体是哪一个，严禁混称**：
     - **「滚动市盈率_PETTM」**（推荐核心口径）：基于过去 4 个季度滚动归母净利润（真 TTM）计算，不受单季淡旺季与偶发收支扭曲，是估值对标与价值分析的首选；
     - **「动态市盈率_PE」**：现价 ÷ 最新单季年化每股收益（年化口径），一季度净利润×4、中报×2，遇单季度业绩突增突减时极易严重失真；
   - **禁止跨口径互乘**：接口返回的「报告期每股收益_EPS」为当前报告期的非年化单期累计值，大模型严禁直接将「动态市盈率」与「报告期每股收益」互乘或互除推导价格，接口已原生计算好「年化每股收益_EPS」与「市净率_PB」。

8. **F10 风格标签盘中动态重算法则（隔日标签禁止盲从）**：
   - 通达信 F10 专线中的概念与风格标签（如 `summary` 下 `table3` 标示的“破净股”、“低市盈率”、“绩优”等）以及静态估值字段（`sjl` 市净率、`sylttm` 市盈率），是由服务端批处理在上一交易日清算后固化生成的（以 `table8` 的清算基准日 `gxrq` 为准），属于**隔日静态数据**；
   - **盘中时效性缺陷与反向风险**：若标的在当前交易日出现大幅波动（如涨停、大涨或大跌），静态标签极易给出与盘中现实完全颠倒的反向结论（例如：标的昨日收盘价 < 每股净资产，标签标“破净股”；但今日盘中股价大涨/涨停，现价已超过每股净资产，实际已经脱离破净状态，但 F10 标签依然显示“破净股”）；
   - **大模型核心红线**：大模型在盘中撰写分析或回答用户估值/风格状态时，**严禁直接照抄 F10 的静态风格标签**！必须优先调用 `stock_quotes` 取得实时「现价」，读取 F10 `table4` 中的「每股净资产_BPS」，以 `当前现价 ÷ 每股净资产` 现场动态重算即时市净率 PB。当且仅当即时 PB < 1 时才可认定为破净，若现价 >= 每股净资产，必须明确告知用户该标的“昨日清算曾破净，但今日盘中已脱离破净”。

9. **亏损标的同比增减正负号解析法则（方向判定红线）**：
   - 通达信及主流金融终端对财务指标同比增长率（如 `gmjlrtbzzl` 归母净利润同比、`kfjlrtbzzl` 扣非净利润同比）遵循权威金融与会计统计标准，采用“利润变动方向”公式计算：$$\text{YoY} = \frac{当期净利润 - 上年同期净利润}{|上年同期净利润|}$$；
   - **亏损公司的正负号特殊含义**：
     - 当公司处于亏损状态（当期归母净利润 < 0）时，**负号（−）表示亏损扩大（业绩进一步恶化）**，如 -24.78% 代表“净亏损同比扩大 24.78%”；
     - **正号（+）表示亏损收窄/减亏（业绩边际改善）**，如 +15.2% 代表“净亏损同比收窄 15.2%”；
   - **大模型核心红线**：大模型在解读亏损企业的 F10 财务指标时，**严禁私自将两个负数相除得出正数并下结论“净利润大幅增长”**，也**严禁望文生义将负号解读为“盈利减少”**。必须先核验报告期利润绝对额（`gmjlr`）是否为负数：若为负数且同比为负，定性表述必须是“亏损扩大”；若为正值盈利企业（如归母净利润 > 0），则按常规正为增长、负为下滑解读。接口已自动注入「归母净利润变动方向判定」与「亏损标的同比解读警示」辅助字段，大模型应直接引用。

10. **纯数字代码正主保全与首位优先律（杜绝基金代码碰撞挤占股票正主）**：
   - 在中国证券市场，6 位纯数字代码存在 A 股股票与开放式公募基金同名并存的现象（如 `002698` 既是 A 股上市公司“博实股份”，也是“博时裕利纯债债券A”；`000001` 既是“平安银行”，也是“华夏成长”）；
   - **正主优先法则**：当用户输入 6 位 A 股代码或 5 位港股代码进行检索时，用户意图 99% 以上聚焦于股票资产。MCPHub 网关底层已内置纯数字代码三轨防御保全机制（腾讯行情专线 + 新浪行情备份 + 通达信官方 F10 摘要表权威反查），**确保与代码精确匹配的股票正主始终稳定置于 `entities[0]` 首位**；
   - **大模型核心红线**：大模型读取 `stock_lookup` 实体结果时，在进行个股分析场景下，**必须优先选用 `entity_type == "A股代码"` 或 `"港股代码"` 的首位正主实体**，绝不能因同代码基金的存在而误认该股票未上市或错读基金净值！

11. **营业利润不可机械加减复算法则（禁止科目粗暴累加）**：
   - 现行利润表中：`营业总收入 − 营业总成本 + 投资收益 + 资产处置 + 汇兑 + 其他收益 + 公允价值变动净收益 ≠ 营业利润`（绝大部分上市公司存在残差，如茅台差 +0.32亿、比亚迪差 -25.21亿）；
   - **差额来源**：通达信 38 列工商业利润表标准模板未收录新金融工具准则下的「信用减值损失」与「资产减值损失」细项，网关已自动核算并注入【营业利润不可加总差额_信用减值与资产减值损失及其他】字段；
   - **大模型核心红线**：财务建模与分析时，大模型**绝对不可试图用收入、成本等代数相加去验证或篡改营业利润**，必须直接以官方披露的【营业利润】、【利润总额】与【净利润】为准！

12. **收盘后五档盘口残量防误导法则（严禁误判多空深度）**：
   - 15:00 收盘后，交易所连续竞价撮合系统已停止工作，五档盘口所剩仅为收盘集合竞价未撤单的极少量静态残量挂单（例如 600519 五档合计仅 84 手）；
   - **大模型核心红线**：大模型**严禁将休市后的微量残单当作真实买卖盘口深度、买卖支撑阻力或多空博弈力量强弱进行推断**！真实有效的五档流动性深度仅在交易日连续竞价撮合期间（9:30-11:30、13:00-14:57）动态全量有效。

13. **A+H 跨市场股本与市值测算核验法则（杜绝股本口径混淆）**：
   - 对于 A+H 两地上市标的（如比亚迪 002594/01211、中国平安、宁德时代等），F10 十大流通股东表统计的流通股本通常为定期报告历史合并流通口径（如比亚迪定期报告 71.70 亿股 = A股流通 34.87 亿 + H股流通 36.83 亿）；
   - 而 quotes 工具返回的【总股本_万股】为交易所实时最新法定全部已发行股本（如比亚迪最新 91.17 亿股，涵盖公积金转增和增发全部已发行份额）；
   - **大模型核心红线**：跨市场估值、AH 溢价率与总市值测算时，切勿将历史定期报告流通额与实时法定总股本混为一谈，严禁用 A 股市价直接乘以包含 H 股在内的合并股本计算 A 股市值！

## 第二章：8 大标准金融工具技术手册与接口对齐规范

### 1. `stock_lookup`（标的代码与名称语义智能检索）
- **底层支撑通道**：通达信 RAG 语义检索向量通道 + 纯数字代码三轨正主保全引擎。
- **功能用途**：输入股票简称、拼音首字母或代码，智能检索出标准 6 位 A 股代码、5 位港股代码及交易所代码。**底层已内置纯数字代码三轨正主保全防御层，彻底解决 A 股代码与公募基金代码碰撞导致的漏检与挤占问题（如 002698 博实股份、000001 平安银行稳定置顶）**。
- **推荐场景**：所有涉及自然语言股票名称的分析任务的第一步。
- **参数规格 (Input Parameters)**：
  - `query` (字符串，必填)：股票名称、拼音缩写或代码（如 `"贵州茅台"`、`"腾讯"`、`"BYD"`）。
  - `range` (字符串，选填，默认 `"AG"`)：市场类型枚举。
    - `"AG"`：A 股（通达信通道，默认）。
    - `"HK-GP"`：港股股票（后续路由至腾讯接口）。
    - `"HK-JJ"`：港股基金。
    - `"JJ"`：内地公募基金（通达信通道）。
    - `"MG-GP"`：美股。
    - `"ZS"`：大盘指数（通达信通道）。
- **调用范式 (Tool Call JSON)**：
  ```json
  {"name": "stock_lookup", "arguments": {"query": "宁德时代", "range": "AG"}}
  ```
- **返回接口数据结构 (Response Structure)**：
  ```json
  {
    "query": "宁德时代",
    "range": "AG",
    "entities": [
      {
        "code": "300750",
        "name": "宁德时代",
        "setcode": "0",
        "market": "SZ",
        "entity_code": "300750",
        "entity_name": "宁德时代",
        "entity_type": "A股代码",
        "entity_setcode": 0,
        "aliases": ["ndsd", "CATL|宁德", "宁德时代新能源科技股份有限公司"]
      }
    ]
  }
  ```

### 2. `market_context`（国内交易日历与市场时钟感知）
- **底层支撑通道**：本地东八区金融日历与交易时钟算法。
- **功能用途**：获取当前东八区北京时间所处的 A 股市场交易状态（盘前集合竞价、早盘中、午间休市、午后盘中、今日已收盘、周末休市）与基准交易日。
- **推荐场景**：在盘前、盘中解盘或盘后总结时，首先调用本工具建立时间锚点，防止“把昨日收盘当盘中”、“非交易日以为开盘中”等时间错乱。
- **参数规格 (Input Parameters)**：无需传入任何参数（空对象 `{}`）。
- **调用范式 (Tool Call JSON)**：
  ```json
  {"name": "market_context", "arguments": {}}
  ```
- **返回接口数据结构 (Response Structure)**：
  ```json
  {
    "current_cst_time": "2026-10-21 15:30:00",
    "market_status": "closed_today",
    "market_status_desc": "今日已收盘 (15:00后结算状态)",
    "is_trading_time": false,
    "reference_trading_date": "2026-10-21"
  }
  ```

### 3. `stock_quotes`（实时盘口微观高频行情与估值指标）
- **底层支撑通道**：
  - **A 股（6 位代码）**：直连**通达信官方专线**，提供 Level-1 基础五档买卖委托挂单、成交量比、内外盘强弱。
  - **港股（5 位代码）**：直连**腾讯免费数据接口**，提供最新价、涨跌幅、买卖一档实时报价。
- **参数规格 (Input Parameters)**：
  - `symbol` (字符串，必填)：证券代码。国内 A 股为 6 位数字（如 `"600519"`、`"000001"`）；港股为 5 位数字（如 `"00700"`、`"09988"`，支持带 `"HK"` 前缀）。
  - `setcode` (字符串，选填)：市场代码（`"0"`=深市，`"1"`=沪市，`"2"`=北交所，`"31"`=港交所）。通常不传，网关底层根据代码自动推导。
- **调用范式 (Tool Call JSON)**：
  ```json
  {"name": "stock_quotes", "arguments": {"symbol": "600519"}}
  ```
- **返回接口数据结构 (Response Structure)**：
  - 顶层标准归一字段：`symbol`, `name`, `setcode`, `market`（如 `上海证券交易所 (SSE)`、`香港交易所 (HKEX)`）；
  - `盘口核心行情`：包含 `股票名称`、`现价`、`涨跌幅_pct`、`涨跌额_元`、`昨收`、`今开`、`最高`、`最低`、`成交量_手`（港股为 `成交量_股`，统一规范为 `int` 消除跨市场类型漂移）、`成交额_元`（港股为 `成交额_港元`）、`日内振幅_pct`、`换手率_pct`（港股已原生内置测算）、`量比`、`外盘_手`、`内盘_手`、`委比_pct`、`委差_手`、`更新时间`、`结算货币`、`涨跌停说明`（港交所主板不设固定 ±10%/±20% 涨跌停限制，实行市调机制 VCM）；
  - `估值与基本盘面`：
    - `总股本_万股`、`流通股本_万股`、`总股本_股`、`流通股本_股`（港股已通过专线与总市值/现价原生推导总股本与流通股本）；
    - `总市值_元`、`流通市值_元`（港股为 `总市值_亿港元`、`流通市值_亿港元`）；
    - `动态市盈率_PE`（现价÷年化EPS）、`滚动市盈率_PETTM`（真TTM）、`静态市盈率_PEStatic`、`市净率_PB`、`年化每股收益_EPS`、`报告期每股收益_EPS`；

### 4. `stock_kline`（多周期历史走势与内置技术指标）
- **底层支撑通道**：
  - **A 股**：通达信专线拉取原始行情，网关纯 Python 原生算法计算指标。
  - **港股**：东方财富高可用行情专线（主力）+ 腾讯财经开放 K 线专线（备份），网关纯 Python 原生算法计算指标。
- **参数规格 (Input Parameters)**：
  - `symbol` (字符串，必填)：标准证券代码（如 A股 `"002594"`，港股 `"00700"`、`"02357"`）。
  - `period` (字符串，选填，默认 `"day"`)：K 线周期。枚举值：`"day"` (日线), `"week"` (周线), `"month"` (月线), `"60m"` (60分钟), `"30m"` (30分钟), `"15m"` (15分钟), `"5m"` (5分钟), `"1m"` (1分钟)。

  - `setcode` (字符串，选填)：市场代码（`"0"`=深市，`"1"`=沪市，`"2"`=北交所，`"31"`=港交所）。默认自动推导。
  - `with_indicators` (布尔值，选填，默认 `true`)：是否自动附带服务端计算好的原生技术指标（务必保持 `true`）。
- **调用范式 (Tool Call JSON)**：
  ```json
  {"name": "stock_kline", "arguments": {"symbol": "02357", "period": "day", "count": 60, "adjust": "none", "with_indicators": true}}
  ```
- **返回接口数据结构 (Response Structure)**：
  - 顶层字段：`symbol`, `name`, `setcode`, `period`, `adjust`, `total_bars`, `indicators_included`, `成交量口径说明`；
  - `成交量口径说明`（港股）：明确指出港股分钟线（1m/5m/15m/30m/60m）仅包含 09:30-16:00 持续交易时段成交量，不含 16:00-16:08/16:10 收市竞价交易时段 (CAS) 撮合量。港交所 CAS 撮合量通常占全天 5%~12%，故分钟线累计成交量略小于日 K 线全天总量系港股交易机制正常特性而非丢损；
  - `klines` 数组（按时间升序排列，每个周期元素包含）：
    - 基础行情：`datetime` (与 `time`), `open`, `close`, `high`, `low`, `volume`（**所有周期统一规范为【股】，周月线已乘100消除漂移**）, `amount`（成交额_元）；
    - 原生技术指标（`with_indicators=true` 时精准附带）：
      - 均线：`ma5`, `ma10`, `ma20`；
      - MACD：`macd_dif` (快线), `macd_dea` (慢线), `macd_hist` / `macd_bar` (柱状图)；
      - KDJ：`kdj_k`, `kdj_d`, `kdj_j`；
      - BOLL：`boll_mid` (中轨), `boll_upper` / `boll_up` (上轨), `boll_lower` / `boll_dn` (下轨)；
      - RSI：`rsi6`, `rsi12` (6周期与12周期相对强弱超买超卖指标)。

### 5. `stock_financials`（A股与港股结构化财务报表三张表）
- **底层支撑通道**：
  - **A 股**：通达信官方财务专用通道（TdxShareCW）。
  - **港股**：新浪港股 F10 主力专线 + 东方财富港股数据中心高可用自动备份容灾双轨通道（现金流量表首选东财 `RPT_HKF10_FN_CASHFLOW_PC`，彻底消除新浪历史停更导致的资产负债表误退）。

    - `"quarter"`：单季度拆分口径（港股已完整透传支持并在报表标题与说明中显式标记）。

- **调用范式 (Tool Call JSON)**：
  ```json
  {"name": "stock_financials", "arguments": {"symbol": "01133", "report_type": "income", "period_type": "report", "limit_periods": 4}}
  ```
- **返回接口数据结构 (Response Structure)**：
  - 顶层字段：`symbol`, `statement_type`, `period_type`, `period_count`, `statements`, `会计口径与说明`；
  - `statements` 数组：核心历史财报列表（按报告期倒序，第 0 项为最新一期），科目全中文化映射；
  - **港股专属标准化字段**：
    - `截止日期` 与 `报告期截止日`：统一为会计期间结束日（如 `"2026-06-30"`），与资产负债表时点语义完全拉齐；
    - `报告期` 与 `报表类型`：统一为报告期类型（如 `"中报"`、`"年报"`、`"一季报"`）；
    - `金额单位`：新浪主力源明确标明 `百万元`，东方财富备份源标明 `元`；
    - `报告币种` 与 `币种`：逐期独立隔离（如 01133 近期为 `美元`，历史期为 `人民币`），多币种切换时自动附带 `跨期币种变动说明`；
    - `每股收益币种单位`：美元报表明确标注为 `美分`（提供 `基本每股盈利(美分)` 及折合美元值），港币报表标注为 `港仙`，人民币报表标注为 `分`；
    - `总负债_测算说明`：当底层数据缺失总负债单项时，底层自动运用会计恒等式精确补齐；
  - **A股专属自陈与自动轧差核算字段**：
    - **利润表（income）**：
      - `营业利润不可加总差额_信用减值与资产减值损失及其他`：底层自动将公式 `营业利润 − (营业总收入 − 营业总成本 + 投资收益 + 其他收益 + 公允价值变动 + 汇兑 + 资产处置)` 轧差核算出的残差，差额由新准则减值损失引起；
      - `利润表加总纪律说明`：告诫下游严禁自行加减科目拼凑营业利润，必须直接采用官方公布的 `营业利润`、`利润总额` 与 `净利润`；
    - **资产负债表（balance）**：
      - `非流动负债不可加总差额_新租赁准则租赁负债等`：核算新租赁准则科目缺失导致的差额；
      - `流动资产不可加总差额_拆出资金及金融细项等`：核算集团金融公司拆出资金等细项差额；
      - `流动负债不可加总差额_吸收存款及金融细项等`：核算财务公司吸收存款等细项差额；
    - **现金流量表（cashflow）**：
      - `补充资料_间接法`：物理独立隔离的二级字典，彻底防止科目遍历加总双计；
      - `经营活动现金流入不可加总差额_收到其他与经营有关现金等`；
      - `经营活动现金流出不可加总差额_支付其他与经营有关现金等`；
      - `筹资活动现金流入不可加总差额_金融借款及发债细项等`；
      - `筹资活动现金流出不可加总差额_金融分红及利息细项等`。

### 场景 A：国内 A 股全景深度研判与舆情交叉验证流（推荐执行顺序）
当用户提问：“请深度分析一下比亚迪近期的走势、基本面，以及市场上关于其海外建厂和降价传闻的真实性”：

   - 调用 `market_context()` 确立国内 A 股当前处于交易中还是已收盘；

## 第四章：异常防御、平滑降级与自愈机制

1. **输入参数防呆（代码与市场标识自适应）**：
   - 若用户传入的 A 股代码不足 6 位（如 `"60051"` 或 `"1"`），必须先调用 `stock_lookup` 校准为 6 位标准代码（如 `"600519"` 或 `"000001"`）。
   - 若为港股标的且用户输入为 `"700"` 或 `"9988"`，网关会自动补齐为 5 位标准格式 `"00700"` 或 `"09988"`，并自动路由至腾讯港股接口。
2. **专线异常时的平滑搜索降级（Fallback）**：
   - 若调用通达信或腾讯专线时遭遇网络超时、服务器维护或未收录的冷门衍生资产，**严禁直接对用户报错中断对话**。
   - 大模型应立刻自动平滑调用 `fallback_web_search(query="[标的名称/代码] 实时行情 财报")` 进行数据兜底，并在回答中礼貌提示用户：“专线实时通道偶发响应延迟，以下数据已平滑切换为全网最新权威聚合数据供您参考”。
3. **国内休市与停牌自愈感知**：
   - 若 A 股标的 `stock_quotes` 返回价格变动为 0 且成交量极小，优先结合 `market_context()` 的 `is_trading_time` 确认是否处于国内休市时段；若在交易时间则提示用户标的可能处于临时停牌状态。
4. **港股盘口特性与接口差异适配**：
   - 港股行情走**腾讯免费数据接口**，默认呈现最新价、涨跌幅、买一卖一盘口及基础市值数据。若无买二至买五深度挂单，属于腾讯公开通道正常特性，大模型应正常呈现买卖一档，无需报告异常。
   - 港股标的的深度 F10（如主力大单、股东人数变化）若专线未收录，应主动借助 `fallback_web_search` 补充香港披露易官方公告或券商研报数据。
