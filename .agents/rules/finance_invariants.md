# 《金融数据开发与代数闭环铁律》(Finance Data Integrity & Accounting Invariants Rules)

> **生效级别**：工作区强制执行规范 (Workspace Mandatory Rules)  
> **适用范围**：A 股 / 港股 / 美股全市场三大财务报表、F10 深度基本面、盘口行情、估值指标与交易时钟  
> **核心军规**：“底层洗净才出门（单一事实源），出门必过安检机（代数恒等闭环），出厂撞遍十二标（12标的测试矩阵），规则焊进规则库（AI自动加载）”

## 1. 核心公理与角色定位 (Core Axioms & Persona)

1. **金融专业性与敬畏心**：
   金融数据是买方投资决策与量化分析的基石。在数据流中，10000 倍的金额量纲膨胀、0.01 的会计不平、换期导致的估值失真，都会导致百万级研报或交易策略产生严重灾难。
2. **严禁带病出厂**：
   数据接口交付给 LLM 或终端用户前，必须具备**数学上的自洽性**。
   任何会计恒等式未闭合的数据，若无法律或会计准则层面的客观依据，一律属于“生产事故级缺陷”，严禁输出。

## 2. 软件工程三大铁律 (The Three Iron Principles)

### 铁律一：代数闭环公理 (Algebraic Closure & Accounting Invariants)
任何对外输出的财务报表与估值指标，必须严格遵守会计与金融恒等式：
1. **资产负债表恒等式**：
   $$\text{资产总计} \equiv \text{负债合计} + \text{所有者权益合计}$$
   - 容差标准：$|\Delta| \le 0.05$ 元（仅允许浮点微小误差）。
   - 若上游天然缺失（如新华保险 601336 在新保险合同准则 CAS 25 下未下发“保险合同负债”等专有科目），**必须就地挂载显式自陈字段**（如 `负债合计不可加总差额_保险合同负债及金融专有科目缺项` 与 `金融负债结构限制说明`），严禁静默伪造或掩盖差额。
2. **工商业利润表恒等式**：
   $$\text{利润总额} \equiv \text{营业利润} + \text{营业外收入} - \text{营业外支出}$$
   - 容差标准：$|\Delta| \le 0.05$ 元。
   - 若单季或中报上游缺失营业外收支，必须根据恒等式反推补齐为 `0.0`，并挂载 `利润总额核算说明`。
3. **龙虎榜代数恒等式**：
   $$\text{买入总额} - \text{卖出总额} \equiv \text{净买入额}$$
   - 必须确保 `billboard_records` 与 `seat_details` 的绝对量纲统一为“万元”，严禁出现 10000 倍单位错标。
4. **行情与估值自洽性**：
   - 现价 / 最新每股净资产（BPS）与市净率（PB）相对偏离不得超过 0.5%。若上游快照滞后发生换期，必须重算真 PB 并挂载 `PB校准说明`。

### 铁律二：单一事实源 (Single Source of Truth, SSOT)
坚决维护“一级净水厂”架构分工，杜绝多头清洗与二次污染：
1. **清洗权彻底下沉 (Engine Level)**：
   所有网络抓取、字段映射、单位换算（如 `BILLBOARD_BUY_AMT / 10000.0`）、汇率反解（港美股法定美元原币）、期次相减与代数推导，**必须且只能在 `mcp_gateway/engines/` 内部完成**。底层洗净才出门！
2. **编排层保持纯净 (Gateway Level)**：
   `mcp_gateway/finance.py` 严禁编写任何二次修改数值、打补丁的业务逻辑。网关只负责路由、参数校验、协议包装与第一道安检门禁。
3. **排查口诀**：*“如果发现外层还要算，说明底层没洗干净，改底层，绝不准在外层打补丁！”*

| 安全门 | 拦截层级 | 核心构件 | 检验方式 | 违规后果 |
| :--- | :--- | :--- | :--- | :--- |
| **第一道门** | 代码级安检机 | `mcp_gateway/invariants.py` | 网关出口装饰器 `@_enforce_gate_invariants` 自动扫描 | 代数未闭合或量纲错标直接阻断报警 |

## 4. 提交代码前的必检 Checklist (Pre-Commit Checklist)

在修改任何代码后、执行 Git Commit 前，开发者与 AI 必须严格执行以下四步：
1. **全套自动化测试执行**：
   ```powershell
   python -m unittest discover -s tests
   ```
   - 必须看到 `Ran 189 tests ... OK`，所有测试项 100% 绿灯。
2. **28 核心标的专项碰撞测试**：
   ```powershell
   python -m unittest tests.test_finance.TestTwelveEliteStocksSuite
   ```
   - 必须 28 项全绿。
3. **最小改动代码审查**：
   ```powershell
   git diff
   ```
   - 检查是否有非必要的无关逻辑修改或格式破坏；
   - 检查所有新增或修改的函数是否具备标准功能块注释（输入、功能、输出）。
4. **文档同步审查**：
   - 若接口参数或字段说明变更，同步更新 `mcphub-finance/SKILL.md` 与 `mcphub-finance/references/tool_api_reference.md`。
